    Wikilink Resolution

    Wikilinks resolve through an extension fast-path and a 4-pass fuzzy heading match, then fall back to the assets directory:

    • Direct — Item Headings links to its exact heading.
    • Aliased — the callout section links with custom display text.
    • Fuzzy (typo-tolerant) — Wikilink Reslution still resolves here thanks to the Levenshtein pass (wikilink reslution → wikilink resolution).
    • Asset image — embeds the demo logo as a base64 data URI in --single mode:
    • Literal in code — `[[not-a-link]]` inside backticks is never treated as a link.

    File Links & Missing Targets

    Markdown links keep standard GFM behaviour, with two extensions:

    • Unsafe javascript: / vbscript: schemes are rejected; http(s), mailto, ftp?, and relative URLs pass through.
    • file:/// links are verified against the filesystem and warn instead of failing: make-believe spec points at a file that does not exist, so compiling this page emits the non-fatal warning File link target not found: "file:///SHOWCASE_NONEXISTENT_QUIET.txt" yet still renders the anchor.
    mdd showcase/showcase.mdd --single -o showcase/showcase.html
# File link target not found: "file:///SHOWCASE_NONEXISTENT_QUIET.txt"

    Fuzzy path repair is also built in: 00_DEV / 00__DEV segment mismatches in a link are corrected automatically when the corrected path exists on disk.

    Escapes & Literals

    • Escaped wikilink — \[[literal]] renders as [[literal]] with no resolution attempt.
    • Literal em-dash — in labels, \— renders a real — without splitting title/subtitle (see the diagram in the next section).
    • HTML not allowed — raw HTML is disabled (html: false); a literal <sup>raw html</sup> shows up as escaped text on this page.

    Backslashes before markdown punctuation behave per GFM.

    Cyclic Flow

    Cyclic Flow — Return Arcs
    QUEUE[QUEUE — pending work items]
WORKER[WORKER — consumes and retries]
QUEUE --> WORKER
WORKER -->|requeues failures| QUEUE
WORKER --> DONE[COMPLETED]

    The back-edge WORKER → QUEUE is detected by DFS colouring, excluded from rank assignment, and drawn as a return arc below the graph. Compiling warns Diagram contains 1 cyclic edge(s); normalized to a DAG for layout (drawn as return arcs).

    Self-Loop

    Self Loop
    PROCESSOR[Processor] --> PROCESSOR

    Self-loops are handled the same way — excluded from ranking, drawn as a side arc that clears the node width.

    Crossing Reduction

    Crossing Reduction
    ROOT[Root] --> LEFT[Left branch]
ROOT --> MID[Mid branch]
ROOT --> RIGHT[Right branch]
LEFT --> OUT[Outcome]
MID --> OUT
RIGHT --> OUT

    Three in, one out — longest-path ranking plus median order within each rank keeps the SVG legible.

    Mirror Mode & Dual-Mode Artifact

    Markdown++ produces a dual-mode artifact with two complementary reading layers:

    1. Read Mode: Clean, publication-grade reading experience with in-margin peek pills (🪞 Q&A / 🪞 Semantic Probe) that keep the main narrative flow clean and undisturbed.
    2. Mirror Mode: An explicit reader-side semantic audit layer where the reader reconstructs the author’s declared conceptual map, answers targeted probes about it, and exposes divergences between the reader’s reconstruction and the author’s declared meaning.

    Toggle modes using the topbar switch or with <kbd>Alt</kbd>+<kbd>M</kbd>.

    Q: What is the difference between Read Mode and Mirror Mode?
A: Read Mode preserves an undisturbed, publication-grade reading experience with in-margin peek pills. Mirror Mode fully expands all semantic probes, Q&A blocks, and reader audit tools across the document.

Q: How does client-side state persist?
A: Probe selections, alignment statuses, and reader questions persist locally in browser localStorage. You can reset all saved state at any time via the Appearance settings modal.

          Runtime: Search, Theme & Navigation

          Everything above is not just static markup — the compiled page ships a runtime:

          • Dual-mode toggle — switch between publication Read Mode and semantic Mirror Mode using the topbar switch or <kbd>Alt</kbd>+<kbd>M</kbd>; in Read Mode, margin pills peek open without moving your reading position; responses and reader notes persist privately in localStorage with instant reset in Appearance settings.
          • Search inside an SVG — type Prose or Collision into the search box above: the matching diagram node/cell lights up with .is-hit, and Prev / Next cycle through results (N / M counter). Case-sensitivity toggle available.
          • Live theme — toggle dark/light with the moon button; every fill inherits var(--accent) and friends.
          • Live accent — open the appearance panel and drag the rainbow picker (or tap a swatch): node borders, edges, headers, favicon, and brand logo recolour instantly.
          • Navigation history — click a wikilink (e.g. to Item Headings) then press <kbd>Alt</kbd>+<kbd>←</kbd> / <kbd>Alt</kbd>+<kbd>→</kbd>: the pill restores scroll position and search state; <kbd>Esc</kbd> steps back.
          • Deep links — each heading and alert carries an anchor (#wikilink-resolution); the copy-link button on hover writes the URL.
          • Back to top — the floating button + scroll progress bar in the header track your place.
          • Mobile — ≤900px collapses the sidebar to a drawer; diagrams/tables overflow with 2px smooth scrollbars.

          Compile Modes

          Single file (default) — everything inline, zero external dependencies:

          mdd showcase/showcase.mdd --single -o showcase/showcase.html

          showcase/showcase.html   # <style>, <script>, base64 asset all in one file

          Split directory — modular output:

          mdd showcase/showcase.mdd --split -o dist/showcase-site/

          dist/showcase-site/
├── document.html
├── style.css
├── app.js
└── assets/mdpp-logo.svg

          Pass --no-diagrams / --no-tables to keep raw DSL, --minify/--no-minify to control compression, and --debug for full stack traces on failure. mdd --spec prints this language specification directly.
